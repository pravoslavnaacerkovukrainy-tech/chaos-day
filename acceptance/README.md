# Независимая браузерная приёмка этапа 1

Сценарии используют только вымышленные дела и изолированное хранилище. Они не читают данные Mac и не предназначены для запуска против развёрнутого сайта.

## Запуск

Нужны Node.js 24, локальный Google Chrome и Playwright Firefox. В корне интеграционного репозитория должны быть собраны server и client согласно `docs/web-v1-api.md`.

```bash
cd acceptance
npm ci
npx playwright install firefox
npm test
```

Playwright сам запускает `npm run dev` из родительского каталога на `127.0.0.1:3100` с `CHAOS_DAY_DATA_DIR=/tmp/chaos-day-acceptance`, `CHAOS_DAY_TESTING=1` и `CHAOS_DAY_ALLOW_FAULTS=1`. Уже запущенный совместимый сервер на этом адресе используется повторно. Другой адрес можно задать через `ACCEPTANCE_BASE_URL`, каталог — через `CHAOS_DAY_DATA_DIR`.

Каждый сценарий полностью сбрасывает тестовое хранилище через `/api/dev/bootstrap`. Прогоны последовательные, чтобы сброс одного сценария не влиял на другой. По умолчанию выполняются оба браузера:

```bash
npm run test:chrome
npm run test:firefox
npm run test:list
```

При падении сохраняются trace и screenshot в игнорируемом `test-results/`.

## Покрытие

- гость без cookie получает 401 и не видит названия разделов; неверный и верный пароль, сессия после reload;
- полный цикл на 1440 px и 390 px: строка, отмена разбора, задача, три даты, перенос, выполнение, повторная команда, дневник, reload;
- управляемый `save_failed`: исходная строка и её id сохраняются, повторное сохранение успешно;
- шесть пустых групп обзора в фиксированном порядке;
- импорт synthetic Mac v1 и v9, сохранение id и объектов при повторе, календарные даты без сдвига, дневник и заметки;
- отказ v10 с объяснением и без частичного импорта.

Локаторы используют стабильные `data-testid` из `client/TESTIDS.md` и accessible roles/names. Служебные API нужны только для сброса, внедрения сбоя и независимой проверки результата UI; основной цикл выполняется через браузер.
