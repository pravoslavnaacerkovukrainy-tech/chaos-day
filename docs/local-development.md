# Локальная разработка и запуск

Техническая записка этапа 1: как поднять приложение локально, чем его проверить и где что лежит.
Продуктовый `README.md` в корне репозитория — отдельный документ владельца, его здесь не дублируем.

Правила методики описаны в [`web-v1.md`](web-v1.md), контракт HTTP-API — в [`web-v1-api.md`](web-v1-api.md).
Этап 1 работает только на `localhost`: публикация, DNS, nginx и VPS относятся к этапу 2
и требуют отдельной команды владельца.

## Требования

- Node.js 24 или новее. Хранилище использует встроенный модуль `node:sqlite`, отдельная база не нужна.
- Рантайм-зависимостей у сервера нет. `npm install` ставит только инструменты разработки:
  TypeScript и Vite.

Проверить окружение:

```bash
node --version    # v24.x
node -e "require('node:sqlite'); console.log('node:sqlite доступен')"
```

Сервер запускается напрямую из TypeScript: Node 24 снимает типы без шага сборки.

## Запуск

```bash
npm install
npm run dev       # http://127.0.0.1:3000
```

При первом открытии приложение просит задать пароль — он хранится только как проверка `scrypt`,
не как текст. Дальше открывается «Место хаоса».

Собранный интерфейс и раздача на одном origin:

```bash
npm run build     # vite build client -> client/dist
npm start         # раздаёт client/dist и /api на одном origin
```

Клиент живёт в `client/` и собирается Vite (`root = client`, вывод `client/dist`).
В разработке `client/vite.config.ts` проксирует `/api` на `127.0.0.1:3000`, поэтому сервер и
Vite можно держать в двух процессах.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP. |
| `HOST` | `127.0.0.1` | Адрес прослушивания. На этапе 1 только localhost. |
| `CHAOS_DAY_DATA_DIR` | `.data` в корне проекта | Каталог файла `chaos-day.sqlite`. |
| `CHAOS_DAY_DB_FILE` | `<data-dir>/chaos-day.sqlite` | Полный путь к файлу базы. `:memory:` даёт базу в памяти. |
| `CHAOS_DAY_TIMEZONE` | `Europe/Kyiv` | Часовой пояс владельца при первом запуске. Дальше хранится в базе. |
| `CHAOS_DAY_SESSION_TTL_SEC` | `43200` | Время жизни сессии, 12 часов. |
| `CHAOS_DAY_TESTING` | пусто | `1` включает пути `/api/dev/*` для приёмки. |
| `CHAOS_DAY_ALLOW_FAULTS` | пусто | `1` разрешает управляемую ошибку сохранения. |

Изолированный запуск для приёмки, не трогающий основные данные:

```bash
CHAOS_DAY_DATA_DIR=/tmp/chaos-day-acceptance \
CHAOS_DAY_TESTING=1 CHAOS_DAY_ALLOW_FAULTS=1 PORT=3100 \
npm run dev
```

## Проверки

```bash
npm test                          # автопроверки правил методики (node --test)
npm run typecheck                 # tsc --noEmit по серверу и тестам
npx tsc -p client/tsconfig.json   # типы клиента (отдельный конфиг, там нужен DOM)
```

Корневой `tsconfig.json` намеренно не включает `client/`: у сервера `lib` без DOM.
Клиент проверяется своим конфигом.

`npm test` запускает проверки без браузера и без сети на вымышленных делах. Они закрывают правила,
которые нельзя отдать на откуп интерфейсу:

- три даты не подменяют друг друга;
- разбор строки места хаоса атомарен;
- снятие не равно выполнению;
- выполнение создаёт одну запись дневника;
- шесть групп обзора без дублей и с пустыми группами;
- повторный импорт сохраняет идентификаторы;
- «Кому обещано» не попадает в дневник;
- срок, записанный календарной датой, не переезжает на соседний день при смене часового пояса.

Отдельно `tests/http-api.test.ts` гоняет сквозные запросы к настоящему HTTP-серверу,
а `tests/persistence.test.ts` проверяет, что состояние переживает перезапуск процесса.

Браузерная приёмка живёт в `acceptance/` (Playwright) и запускается по своей инструкции —
это отдельный npm-проект со своими зависимостями.

## Импорт данных из Mac-версии

Импорт принимает `Архив.json` или `entries.json` клиента Mac форматов v1–v9. Неизвестная более
новая версия отклоняется с объяснением, а не обрезается молча. Повторный импорт того же файла
не плодит копии: идентификаторы сохраняются.

Исходный файл Mac первый выпуск не изменяет. Боевой `entries.json` владельца в проверках
не используется — только синтетические файлы из `fixtures/`.

## Устройство каталогов

```
docs/            заметка этапа, контракт API и эта записка
src/server/      HTTP-сервер, хранилище SQLite, правила, импорт и экспорт
client/          интерфейс (ветка фронтенда, собирается Vite в client/dist)
tests/           автопроверки правил и сквозные HTTP-проверки
fixtures/        синтетические файлы Mac v1–v9, все дела вымышленные
acceptance/      браузерные сценарии приёмки (ветка приёмки, свой package.json)
```

## Границы этапа 1

Размещение на `day.osintradar.net`, DNS, nginx, сертификаты, systemd и откат — этап 2, требуют
отдельной команды владельца. Синхронизация с Mac, контексты, повторы, напоминания, ИИ, привычки,
Telegram и файлы в первый выпуск не входят.

## Приватность

Данные лежат в одном файле SQLite в `CHAOS_DAY_DATA_DIR`. Аналитики, телеметрии и сторонних
сервисов нет. Отдельный журнал запросов сервер не ведёт, поэтому тексты задач и заметок
в логи не попадают. Пароль не хранится в виде текста и не появляется в ответах и экспорте.
