## Экраны этапа 1

Девять экранов, все на одном origin, всё состояние в одном снимке `GET /api/state`.

| Экран | Что показывает |
|---|---|
| **Вход** | Задание пароля при первом запуске, затем вход. Без входа не отдаются даже названия разделов. |
| **Место хаоса** | Строки быстрой корзины. «Не может ждать», «Это задача», «Это заметка», «Снять». |
| **План** | «Сегодня» и любая выбранная дата: день работы, незавершённое с прошлых дней, наступивший срок, угроза. Команда «Перенести». |
| **Проекты** | Результат, что нужно выяснить, дата пересмотра, один следующий шаг, сфера, архив. |
| **Ожидаю** | Открытые задачи в статусе «Ожидаю»: кого или чего ждать и когда проверить. |
| **Обзор** | Шесть групп в фиксированном порядке, всегда шесть, пустая группа остаётся с текстом «Сейчас здесь ничего нет». |
| **Все задачи** | Общий список с переключателями «Показывать выполненные» и «Показывать снятые». |
| **Заметки** | Markdown вне календаря, дерево папок, поиск только внутри раздела. |
| **Дневник** | Факты дня с отметкой времени и пометкой «на чём остановился». |

Поиск одного раздела не переключает раздел. Единый поиск по делам
(задачи, неархивные проекты, строки места хаоса) живёт в разделе дел.

## Модель

Одно хранилище SQLite (`node:sqlite`), одна учётная запись владельца.

- **Задача** — текст, сфера (`work` / `personal`), проект, статус
  (`ready` «Можно делать», `waiting` «Ожидаю», `paused` «Отложено», `removed` «Снято»,
  плюс унаследованный `inbox` из старых файлов), подробности, кого или чего ждать,
  «Кому обещано», «Обещание под угрозой», причина снятия, шаги.
- **Три независимые даты**: `deadline` (срок результата), `day` (день работы), `review_date`
  (дата пересмотра). «Перенести» меняет только `day`.
- **Проект** — результат, неопределённость, дата пересмотра, один следующий шаг, сфера, архив.
- **Строка места хаоса** — ещё не задача и не заметка: без сферы, проекта и дат.
- **Запись дневника** — факт, «на чём остановился», время, необязательная связь с задачей.
- **Заметка** и **папка заметок** — дерево, вне календаря.
- **Шаг** — часть одной задачи: свой id, текст, выполнение, порядок. Без своих сроков, проекта и дневника.

### Календарные даты

Известный дефект Mac-версии — срок, записанный календарной датой, уезжает на соседний день
при смене часового пояса. В веб-версии он не повторяется:

- все три даты хранятся как текст `YYYY-MM-DD`, а не как момент времени;
- часовой пояс владельца хранится рядом с данными (`meta.timezone`) и участвует в расчёте «сегодня»;
- ключ дня записи дневника вычисляется в этом же часовом поясе и пересчитывается при его смене.

## Правила, которые проверяются автопроверками

1. Три даты не подменяют друг друга: перенос дня работы сохраняет срок и дату пересмотра.
2. Разбор строки места хаоса атомарен: строка уходит только вместе с успешно сохранённой задачей
   или заметкой; отмена и ошибка сохраняют прежний идентификатор строки.
3. Срочная строка, ставшая задачей, получает «Обещание под угрозой» и не получает дат.
4. Снятие не равно выполнению: причина обязательна, `completed_at` не заполняется, запись дневника не создаётся.
5. Выполнение создаёт ровно одну запись дневника; повтор не создаёт вторую.
6. Возврат в работу удаляет связанную запись, только если её не меняли.
7. Шесть групп обзора: фиксированный порядок, первое совпадение побеждает, дублей нет, пустые группы остаются.
8. Повторный импорт сохраняет идентификаторы и не плодит копии.
9. «Кому обещано» не копируется в запись дневника.
10. Файл неизвестной более новой версии отклоняется с объяснением, а не молча обрезается.
11. Задачу с шагами нельзя удалить, пока шаги явно не удалены.

## Импорт и экспорт

**Импорт** читает форматы Mac v1–v9 (`Архив.json` или `entries.json`): заголовок `format: "daylog"`,
версия 1–9, даты ISO-8601, `day` уже календарным ключом. Версия старше 1, старше 9 или чужой
`format` отклоняются с русским объяснением. Импорт идемпотентен по идентификаторам:
повторный прогон того же файла не создаёт копий. Моменты времени `deadline` и `review_date`
пересчитываются в календарный день в часовом поясе владельца.

**Экспорт** отдаёт JSON (полный снимок в том же формате `daylog`, чтобы его читала Mac-версия)
и Markdown. Черновик несохранённого поля в экспорт не попадает: сервер отдаёт только записанное.

## Стек и запуск

Node 24 и встроенный `node:sqlite`, TypeScript, единый npm-проект без рантайм-зависимостей.
Сервер запускается напрямую (Node 24 снимает типы без сборки), клиент — `client/index.html`,
`client/src/`, сборка Vite в `client/dist`, которую сервер раздаёт на том же origin.
Команды и переменные окружения — в [`docs/local-development.md`](local-development.md) и в контракте.
